# 空正文行：各家读法与语料

只有时间标签、没有正文的行（`[00:20.82]`）有两种读法：

- A，结束标记：上一行到此结束，不产生新行。
- B，空行 / 清屏：产生一条空正文行，在滚动列表里占一格。

LRC 是事件模型（每个时间戳是一次状态切换），不是 SRT 那样的区间模型，所以单行
显示下两种读法在时间上等价，上一行都在这一刻结束。差别只在时间以外：

1. 空行能不能当参考行（翻译）的锚点。
2. 布局：滚动列表里空行占不占一格。

本库选 A，取舍见 [semantics.md](../design/semantics.md#空正文行)。

## 各家实现

"源码"表示读过实现，"文档"表示只有规范或说明。

| 实现 | 读法 | 依据 | 连续空行 | 同时间戳 / 翻译 |
| --- | --- | --- | --- | --- |
| FFmpeg `lrcdec` | B | 源码：每个时间戳都入队，时长取到下一事件为止 | 每个都是空事件 | 无翻译概念 |
| mpv | B | 源码：`sd_ass.c` 注释 "empty lines are useful in LRC" | 保留 | 无 |
| Kodi `script.cu.lrclyrics` | B | 源码 | 保留 | 无 |
| lrcget / LRCLIB | B | 源码；lint 要求用空行标记歌词结束 | 保留 | lrcget 有与下一句同时间戳的空行弄坏旧播放器的 issue |
| lrc-kit / pylrc / justan/lrc | B | 源码：每个时间戳都产生一行 | 保留 | 无合并 |
| AMLL `@applemusic-like-lyrics/lyric` | A | 源码：空行补上一行的显式结尾 | 第二个起丢弃 | 空行不当宿主也不当翻译 |
| SPL | A | 文档：纯结束标记"不参与翻译识别"，示例里空行与下一句同时间戳 | 未规定 | 明确排除 |
| Subtitle Edit `Lrc.cs` | A | 源码：读时作上一行结尾后删除；写时间隔大于 100ms 补结束标记 | - | - |
| LDDC | 近似 A | 源码：设上一行结尾后删除空行 | 逐个设结尾后删除 | 同时间戳的后一行进翻译列表，空行占了主位 |
| lrc-file-parser（LX Music 使用） | 可配置 | 源码：默认删除空行 | - | 保留空行时与 LDDC 同样误挂 |
| VLC | 不适用 | 源码：没有 LRC 解析，歌词视图读 ID3 SYLT | - | - |

要点：

- 两派在时间上一致，分歧只在空行算不算一个元素。
- 播放器与通用解析器多为 B，面向富显示的新实现（AMLL、SPL、LDDC）为 A。
- 翻译误挂只在"同时间戳合并为翻译"与"空行算一行"同时成立时出现（LDDC、
  lrc-file-parser 的保留模式）。AMLL 与 SPL 靠"无正文行不参与翻译匹配"避开。

没有找到权威资料的：网易云、QQ 音乐、Poweramp、Musicolet、foobar2000 / ESLyric。

## 其它字幕格式怎么表达"清屏"

| 格式 | 模型 | 清屏写法 | 转换器的映射 |
| --- | --- | --- | --- |
| SAMI | 事件 | `<SYNC><P>&nbsp;` | FFmpeg 解码器显式跳过空事件，只截断上一条；Subtitle Edit 也不产生空段落 |
| PGS / SUP | 事件 | 不含 object 的 composition | FFmpeg：上一条的结束时间取下一条的开始，下一条可以不含 object |
| CEA-608 | 屏幕状态 | EDM / ENM / EOC 命令 | 缓冲模式下成为上一条 cue 的结束 |
| DVD VobSub / DVB | 混合 | stop-display 命令 / 空页或超时 | 成为上一条的结束 |
| MicroDVD / MPL2 / SubViewer | 区间，结尾可空 | 显式结尾；空结尾取下一条开始 | - |
| SRT / WebVTT / TTML / ASS | 区间 | cue 之间的空隙 | - |

成熟转换器把无正文的事件读成"上一条到此结束"。FFmpeg 的 LRC 路径会额外留下空
cue，与它自家 SAMI 解码器丢弃空事件的做法不一致，看起来是实现的副产物。

## 语料

本地曲库 6652 份 `.lrc`，只读统计。判定空行用的是独立的简化正则，不经过本库解析器，
所以与 [spl.md](spl.md) 的口径略有出入（28748 对 28836，语料快照也不同）。

| 指标 | 数值 |
| --- | --- |
| 空正文行 | 28748 |
| 连续段（中间的无标签空白行不打断） | 单个 25585，2 个 1324，3 个及以上 136，最长 9 |
| 至少有一段连续 2 个以上的文件 | 430 |
| 连续段中时间戳全相同 / 递增 | 914 / 546 |
| 文件末尾的空行段 / 前面没有正文的空行段 | 1718 / 173 |
| 用尖括号写的空 cue（`<00:01.000>` 独占一行） | 0 |

- 递增的连续段看样本基本是间奏里每隔几秒一个空时间戳，记录"这段时间没有歌词"，
  不是用一串空行把相邻行挤出可视范围的表演写法。后者在这份语料里很少。
- 时间戳全相同的段是同一个结束标记重复写，按 B 读会产出成堆的重复空行。本库把
  它们计为冗余结束标记（`ParseReport.end_markers_redundant`）。

按本库的读法，同一份语料（6646 份）解析时结束标记的去向：

| 去向 | 个数 |
| --- | --- |
| 给上一行补上结尾 | 26053 |
| 与上一行已有的结尾重合（冗余） | 1285 |
| 被忽略：前面没有歌词行 | 219 |
| 被忽略：不晚于上一行的开头 | 328 |
| 被忽略：上一行已在别的时刻结束 | 788 |

## 空 cue 的来源

真实曲库里没有尖括号空 cue，它们来自本库自己的输出：`dumps()` 写空正文行、
`from_srt()` 读空 cue。另一个来源是旧版本写出的文件：0.3.x 默认用 2 位尾数写
时间标签，上游歌词里常见的"`[t-1ms]` 空行 + `[t]` 歌词"会被截成同一个时间戳，
写成"空行 + 同时间戳歌词"。0.4.0 及更早的解析器把这种形状读成"一条空行，歌词
是它的翻译"。0.4.1 起空行改读作结束标记，0.5.0 起空 cue 也不再当锚点或宿主，
这类文件读回来都是正常的歌词行。
